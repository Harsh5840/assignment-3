# API Integration CLI Tool

A powerful command-line interface tool built with TypeScript and Node.js that fetches data from JSONPlaceholder API, merges it intelligently, and caches it locally for efficient access.

## Features

✅ **Smart Data Merging**: Combines Users and Posts data to display author names instead of raw user IDs  
✅ **Intelligent Caching**: 1-hour TTL caching with automatic expiry detection  
✅ **Error Handling**: Comprehensive error handling for network issues, timeouts, and malformed data  
✅ **CLI Commands**: `list` with optional filtering and `show` for detailed post information  
✅ **Type-Safe**: Full TypeScript strict mode implementation  
✅ **Colored Output**: Beautiful terminal formatting with chalk  
✅ **Parallel API Calls**: Fetches users and posts simultaneously for optimal performance  

## Tech Stack

- **Language**: TypeScript (Strict mode)
- **Runtime**: Node.js
- **HTTP Client**: Axios (with 5-second timeout)
- **CLI Framework**: Commander
- **Formatting**: Chalk
- **Storage**: Local JSON file (`data_cache.json`)

## Architecture

### types.ts
Defines TypeScript interfaces:
- `User`: JSONPlaceholder user data
- `Post`: JSONPlaceholder post data
- `MergedPost`: Combined structure with author names
- `CacheData`: Cached posts with timestamp
- `ApiResponse<T>`: Standardized response wrapper

### api.ts
Handles API integration:
- **fetchUsers()**: Fetches users from `/users` endpoint
- **fetchPosts()**: Fetches posts from `/posts` endpoint
- **mergePosts()**: Combines users and posts, maps userId to author_name
- **fetchAndMergeData()**: Orchestrates parallel fetching and merging
- **handleApiError()**: Centralized error handling for network issues

**Why Parallel Fetching?** Both endpoints are independent, so fetching them simultaneously (using `Promise.all`) improves performance significantly.

**Why Merge Strategy?** Instead of displaying raw userIds, we create a lookup map for O(1) access and enrich posts with author names for better UX.

### cache.ts
Implements caching logic:
- **isCacheValid()**: Checks if cache exists and is less than 1 hour old
- **readCache()**: Loads data from `data_cache.json`
- **writeCache()**: Saves merged posts with current timestamp
- **clearCache()**: Deletes cache file for manual refresh
- **getCacheRemainingTime()**: Returns seconds until cache expiry

**Why 1-Hour TTL?** Balances between API rate limits and data freshness. Adjustable in `cache.ts` if needed.

### index.ts
CLI entry point:
- **initializeData()**: Loads cache or fetches fresh data on startup
- **handleListCommand()**: Displays posts with optional filtering
- **handleShowCommand()**: Shows detailed post information
- **setupCliCommands()**: Configures commander with all commands
- **main()**: Orchestrates initialization and command execution

**Why Separate Concerns?** Each function has a single responsibility, making the code maintainable and testable.

## Caching Details

The cache file (`data_cache.json`) stores:

```json
{
  "posts": [
    {
      "id": 1,
      "title": "sunt aut facere repellat...",
      "body": "quia et suscipit...",
      "userId": 1,
      "author_name": "Leanne Graham"
    }
  ],
  "timestamp": 1733539380123
}
```

- **Timestamp**: Unix milliseconds for accurate expiry checking
- **Posts**: Array of merged posts with author names
- **Duration**: Cache is valid for 1 hour (3,600,000 ms) from creation

## Performance Optimization

1. **Parallel API Calls**: Both endpoints fetched simultaneously
2. **O(1) Lookup**: User mapping uses a Map for instant author name retrieval
3. **Caching**: Avoids redundant API calls within 1-hour window
4. **Efficient Filtering**: Case-insensitive string matching in-memory
5. **Timeout Protection**: 5-second request timeout prevents hanging

## API Details

### JSONPlaceholder Endpoints

**Users**: `https://jsonplaceholder.typicode.com/users`
- Returns array of 10 users
- Each user has: id, name, username, email, phone, website, company

**Posts**: `https://jsonplaceholder.typicode.com/posts`
- Returns array of 100 posts
- Each post has: userId, id, title, body
